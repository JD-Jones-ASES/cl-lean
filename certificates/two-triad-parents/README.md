# Two-triad parent search proposals

These records are **native feasibility evidence, not Lean certificates**.
No theorem imports them. Four parent covers now have separate ordinary-kernel certificates in
`TwoTriadDisjoint251.lean`, `TwoTriadOverlap263.lean`,
`TwoTriadOverlap307.lean`, and `TwoTriadOverlap347.lean`, generated by
`scripts/generate_two_triad_lean.py`
and justified by proved finite checkers. These JSON records do not supply
those proofs. The third-parent proposals remain unformalized.

The tuples use parameters `(1,r,x,y)` in the three families defined by
`twoTriadTuple` and `twoTriadModularTuple`. Lean proves that this first-
coordinate normalization loses no possible field tuple: a zero first
coordinate supplies an extra form, and a nonzero scalar preserves the
conclusions. The native search enumerates all three remaining residues.
It uses every prime-grid time and removes only zeros of projected short
forms. Every surviving obstruction is checked again using literal residue
inequalities and the original 116 coefficient vectors.

| Prime | Parent | Additional restriction | Surviving normalized tuples |

| 251 | Disjoint triads | None | 0 |
| 263 | One common coordinate | None | 0 |

| 1009 | Two common coordinates | Outside the six proposed ratio orbits | 0 |

For the last three rows, the proposed ratios are

```
B/A = 3, 4, 7, 10, 5/3, 9/2,
```

together with their negatives and reciprocals in the finite field (24
values at each recorded prime). These are proposed exceptions, not a
proved integer classification. The three searches do not establish an
integer lift or the global Question 6.6 theorem.

The third parent cannot satisfy the same exception-free assertion as the
first two at 223: `TwoTriadModularControls.lean` proves this using the actual
near-tight tuple `(1,3,4,5,18,46)`. That theorem is kernel-checked and does
not rely on the native record.

## Candidate prime selection

`scripts/explore_two_triad_candidate_primes.py` selects proposed sets of
133 disjoint-parent primes from 251 through 1237 and 129 one-overlap-parent
primes from 263 through 1301. The committed record covers 335 parent-prime
checks; its successful searches are still native evidence only. It groups projected
forms by their last-coordinate root slope and uses parameter symmetries
with exact multiplicities. The original literal-form search remains a
separate implementation. The `--controls` mode compares all survivor counts
on 16 positive and negative cases at primes 31, 179, 223, 251, 263, 443,
607, and 1009.

The one-overlap orbit reduction is now proved in
`TwoTriadOverlapSymmetry.lean` and used by the ordinary-kernel certificates
at 307 and 347. Swapping the nonshared coordinates within either triad and
exchanging the triads reduces the search to `0 ≤ r ≤ x ≤ p/2`. The proof
transports both good times and nonzero projected forms. It includes zero
parameters, repeated residues, equal ratios, and the involution's fixed
point. The final parameter still ranges over every residue. The search
checks 11,935 pairs at 307 and 15,225 pairs at 347, instead of 94,249 and
120,409; Lean verifies these representative counts too. The genuine
prime-31 obstruction cannot pass the new block checker with valid inputs.

The slope grouping and disjoint-parent orbit reductions remain **native
optimizations only**. The original certificates at 251 and 263 still check
full normalized residue ranges. No native search output supplies a cover
proof. The fixed prime assembly now inserts all four actual certificates,
leaving exactly **132 disjoint-parent and 126 one-overlap-parent covers**
as explicit hypotheses. The certificate at 347 also expands the unconditional
finite norm application to `3*sum(v_i^2)<347^2` for the one-overlap parent.
The global parent classification and Question 6.6 remain unfinished.

```bash
python3 -O scripts/explore_two_triad_candidate_primes.py --controls --output /tmp/parent-controls.json
cmp /tmp/parent-controls.json certificates/two-triad-parents/native-candidate-controls.json
python3 -O scripts/explore_two_triad_candidate_primes.py --output /tmp/parent-candidates.json
cmp /tmp/parent-candidates.json certificates/two-triad-parents/native-candidate-primes.json
python3 -O scripts/generate_two_triad_prime_lists.py --check
```

The optional `--resume` accepts completed native records; a fresh replay
omits it. Timings are not included in the deterministic output.

Check the generated Lean certificates and build the reduced searches locally:

```bash
python3 -O scripts/generate_two_triad_lean.py --check
lake build LonelyRunner.TwoTriadCandidatePrimes LonelyRunner.TwoTriadOverlapControls
```

The heavy proof blocks depend on their predecessors, so the two new covers
compile sequentially. No GitHub Actions run is required.
